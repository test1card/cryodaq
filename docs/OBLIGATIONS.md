# Obligations register

Every owner direction that is **deferred behind a trigger condition** has one
row here. This file exists because two owner directions recorded 2026-07-31 in
an out-of-tree working file were invisible to repository search and sat
undischarged for nine days after their trigger fired. The register is the
single home for such directions: other documents may reference a row by its ID
but must not restate the table.

Rules:

- **One row per obligation, append-only IDs.** A superseded row changes status;
  it is never deleted.
- **Status vocabulary:** `PENDING` (trigger not yet true) · `DUE` (trigger
  true, acknowledged, not started) · `IN-PROGRESS` · `DONE` (discharge evidence
  cited) · `DROPPED-BY-OWNER` (his word cited).
- **Trigger vocabulary** (kept machine-checkable where possible so a guard can
  evaluate rows from the tree alone): `merged:PR-N` (the PR's merge commit is
  reachable from the default branch) · `marker:<file>:<text>` (the file
  contains the marker text) · `manual:<condition>` (evaluated by people/agents;
  a guard treats it as never auto-firing).
- A planned guard (deferred while the current PR queue is open, because a new
  tracked test module moves the changed-Python count that every open PR
  carries) will fail the docs gate when a machine-checkable trigger is true
  while its row still says `PENDING`. Until it lands, OB-010 tracks the guard
  itself and this register is checked by reading it.
